# 从强化学习到具身任务

强化学习提供目标与策略优化框架。把它用于机器人，还需要把抽象变量落实为传感器、控制接口与评测条件。

## 先写任务定义，再选算法

以机械臂把物体移到目标区域为例：

| RL 概念 | 需要具体写出的内容 |
| --- | --- |
| 状态 | 物体与机器人位姿、速度、接触状态；训练时是否可读取 |
| 观测 | 相机、本体状态、历史窗口及其噪声和延迟 |
| 动作 | 关节力矩、目标关节角、末端位姿增量；单位与坐标系 |
| 转移 | 控制频率、仿真步长、动作保持时长与执行器限制 |
| 奖励 | 任务进展、成功信号、能耗或动作平滑项及其尺度 |
| 边界 | 成功、失败、碰撞与采样时间上限怎样处理 |
| 初始分布 | 训练与测试的物体位置、质量、外观和场景范围 |
| 评测 | 成功判定、试验数、干预次数、失败类型与原始记录 |

同一 PPO 实现，换一种动作语义或执行频率，就可能对应完全不同的控制问题。奖励项较高也可能只说明策略利用了奖励设计的漏洞。

## 沿已有知识补齐三个接口

**观测到状态表示**：MDP 的充分状态在部署时可能不可得，需要处理部分可观测性。训练时可见的特权信息若进入 actor，部署时就必须能提供或替代。

**策略到执行器**：策略的输出可能交给底层 PD 控制器，而不是直接变成电机力矩。学习策略与传统控制器的职责需要分别说明。

**奖励到任务评价**：训练奖励服务优化，评测指标服务判断任务是否完成。报告成功次数/总次数，并将动作延迟、观测噪声等变化单列对照。

## GRPO / GSPO 带来的比较视角

可以比较一组任务尝试的相对反馈，也可以研究动作序列的似然与长度。但语言 token、动作块和物理控制步的语义不同；机器人轨迹还受动力学、接触、重置与实时反馈约束。

因此这部分先用于理解优化单位与信用分配，不预先承诺它会优于机器人任务中的其他方法。

## 下一份具体实验

在低维连续任务上明确观测和动作，再选择一个现成算法做基线。保留配置、代码版本与多种子结果，只改变一个因素检查性能变化。等这个流程稳定后，再进入模仿学习、视觉输入与更复杂的策略。

当前 [GridWorld](../labs/gridworld.md) 只能验证简化离散环境里的规划和学习，不提供机械臂、真实控制或 Sim2Real 的证据。
